# Using Codelore

Use these project skills from a [supported coding harness](harness-support.md) opened on the Codelore repository. Give the session access to a local checkout of the target repository, or a public repository URL it can fetch. Private repositories require access already granted to the active session. Your coding harness controls model access; there is no Codelore API key to configure.

## Review a repository

1. Identify the checkout and revision to inspect. Mention whether uncommitted files, tests, generated files, or vendored code belong in scope.
2. Ask for the complete workflow. For example:

   ```text
   Use the codelore-workflow skill to review D:\path\to\target-repo at HEAD.
   Include tests, exclude generated files, and cover the file map,
   architecture, one request trace, dependencies, health, and setup.
   Cite source files and list any checks you could not run.
   ```

3. Read the reported revision and coverage limits before acting on findings. The coordinator should cite source paths or command output for material claims. A numerical health score appears only when the [coverage rules](../.agents/skills/codelore-health-insights/references/scoring.md) are met.

The workflow uses [`codelore-workflow`](../.agents/skills/codelore-workflow/SKILL.md). Its matching `codelore_coordinator` agent can assemble specialist findings when the host supports agents; the skill also works in one session without delegation. Use the invocation syntax in [Harness support](harness-support.md) when you want to select it explicitly.

## Ask a focused question

Invoke a specialist when you need one part of the review:

```text
Use the codelore-codebase-qa skill on D:\path\to\target-repo at HEAD.
Where is authentication enforced? Cite source lines and relevant tests.
```

```text
Use the codelore-dependency-audit skill on D:\path\to\target-repo at HEAD.
List direct dependencies and identify verified advisories. State the
advisory source and date, and mark anything you could not check.
```

The [feature coverage table](../.agents/skills/codelore-workflow/references/feature-coverage.md) names all 11 skills and matching agents. Use the architecture, tracing, file explorer, health, onboarding, and visual report skills for their corresponding questions.

## Compare revisions or request an export

For a later review, give the previous and current commits:

```text
Use the codelore-refresh skill to compare commit <previous-sha> with HEAD in
D:\path\to\target-repo. Summarize new, changed, and resolved findings,
and include a shareable Markdown report.
```

Reports appear in chat unless you request a file. Ask for a Mermaid or DOT diagram, graph data, or a local interactive report when you need a visual artifact. An interactive view is optional, and a 3D view is not generated by default. Scheduled refreshes and notifications require a scheduler and delivery channel provided by your host; asking for a one-time comparison does not enable monitoring.

## Interpret the result

Each material finding should include a claim, source reference or command output, method, uncertainty, and a next action where useful. Treat static code inspection as evidence of what code declares, not proof of runtime behavior. The suite should report unavailable sections explicitly and should not fill them with the UI's demo data. Repository contents may be sent to the model provider configured for your coding session; review that host's data handling terms for sensitive code.
